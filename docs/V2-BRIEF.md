# V2 任务书（所有知识 Worker 必读）

> 背景：v1 的 159 条规则经独立审计与实测回归后，被判定**不可执行、部分结论注水、存在伦理风险**。
> v2 的目标不是「写得更多」，而是**让引擎真的能跑，并且跑得对**。
> 基线（v1 实测）：引擎案例匹配率 **17.8%**（8 match / 8 partial / 5 mismatch / 24 unsupported，共 45 条真实案例）。

## 〇、五条不可协商的硬约束

任何一条不满足，产出视为未完成。

| # | 约束 | 依据 |
|---|---|---|
| **H1** | 每条规则必须二选一：给 `machine: { when: <DSL>, then: [...] }`，或显式标 `advisory: true` | 审计 P0-1：v1 的 159 条规则 `when` 全是自然语言，引擎 0 条可执行 |
| **H2** | `machine.when.field` 只能取 `knowledge/facts.json` 里的字段 | 引擎对未知字段**只会静默不触发**，不报错。这是最隐蔽的失效模式 |
| **H3** | 所有数字阈值只能取自 `knowledge/standards.json` 的 `hard` 项；`derived` 项**禁止**进入硬判定 | 审计发现同一量在多处有不同阈值；derived 是反推值 |
| **H4** | 面向用户的措辞必须过 `knowledge/ethics-policy.json` 门禁；原始语料结论**不得直接渲染** | 审计伦理节 10 条（6 条 P0）。**语料真实不是上线理由** |
| **H5** | 证据 `quote` 必须是转写口语原文；标题（desc）不能当引文 | 校验器会逐条溯源；ASR 错字可用 `--fix` 看归一化结果，但引文写法以能溯源为准 |

## 一、v2 必须修的：审计 P0（按影响排序）

1. **补齐 `machine` 层**。优先级：`scoring` → `matching` → `band` → `demographic`。修不了的（语料只给了观点没给判定条件）就老实标 `advisory: true`——**标了不是失败，假装可执行才是**。
2. **百人位次口径冲突**：同一个 5.3 分对应「第 6-7 / 第 18-19 / 前 20 / 第 23-24 名」四套口径。**只输出区间（约前 5%–20%），禁止单条精确名次**。
3. **「有争议的班花/班草」= 5.2–5.3 还是 5.5**：两处口径，影响 5.5 门槛判定。请给定分条件（场景/性别/是否含包装），给不出就标 conflict 并由 `advisory` 承载。
4. **「高置信」注水**：同一场直播切成多条短片**不算独立证据**。判定标准改为：≥3 条证据且**跨 ≥2 个不同账号**且**不是同一话题的重复表述**。不满足的一律降为 `medium`。
5. **单例个案不得写成市场规则**：只有 1 条语料的，要么标 `low` 并写进 `advisory`，要么删。
6. **机构营销话术要与市场规律分开**：「报名看主页」「2000 万局」这类是获客话术，不是择偶规律。

## 三、v2 必须遵守：数字与冲突的处理方式

来自 `knowledge/standards.json`（89 条标准：hard 48 / soft 39 / derived 2）与 `AUDIT-v1.md` 的矛盾总表。

**最影响实现的 5 个矛盾，处理方式已定：**

| 矛盾 | 处理 |
|---|---|
| 颜值 5.0–5.5 的百人位次（前5-6 / 第6-7 / 第18-20 / 前20 并存） | 只用区间（约前 5%–20%），**禁止单条精确值** |
| 收入（全国 10 万/年 vs 太原月 5000 即合格） | **必须带城市系数**，不能全国一刀切 |
| 男性身高（硬件表 175+ / 5.5 checklist 光脚 180 / 175 被 6 分封印 / 心智首选边界 172→180） | **按用途分线**，不得收敛成单值。`machine` 条件里要写明用于哪个判定 |
| 女性年龄门槛（长沙 30 岁以下 / 山东·东三省 98 后 / 高社会能量男个人上限 28-29） | 分条件，按活动类型与目标人群 |
| 「有争议的班花」5.2-5.3 vs 5.5 | 见 P0-3 |

**已知空洞（不要假装有）**：女生版硬件评分表缺失；1-2.5 与 7.5-8.4 无锚点；「素颜分/广义分/顶美」无计算阈值；全库**没有**任何「每差 1cm / 1 岁 / 1 万」的换算率（v1 有 worker 想编，已制止）。

## 四、v2 必须过滤：伦理（`knowledge/ethics-policy.json`）

**架构原则：内部结论与用户措辞分离。**

- `then` / `when`（内部）：可以保留原始语料真相，用于建模准确。
- `userFacingText`（渲染）：必须过策略。P0 级命中会让构建失败。
- `evidence.quote`（取证）：**保持原文不改**，不参与伦理扫描（改了溯源就断了）。

典型改写对照（**不在此处复现有害原句**——逐字口径与正则见 `knowledge/ethics-policy.json` 的 `bannedPatterns`，那里是策略定义本身）：

| 策略 id | 原始语料口径的**类别** | 用户可见措辞 |
|---|---|---|
| E2 | 以身体特征与残障/脱发做等价 | 体重区间 + 健康建议；严禁等价物 |
| E3 | 把人品/性格归因于性别与经济状况 | 高冲突沟通风格在相亲初期会降低匹配成功率（两性同样适用） |
| E5 | 对年龄/青春明码标价 | 部分客群对婚龄窗口要求较严（给中性门槛数字） |
| E6 | 年龄贬损等级化 | 30+ 面临年龄门槛，需用其他筹码补位 |
| E7 | 按地域出身给人群排序 | 删除人群排名，只保留城市产业与供需结构描述 |
| E8 | 对单亲家庭与儿童的污名化 | 带孩再婚匹配周期更长、需更多时间线 |
| E9 | 生育/性筹码化 | 双方对生育安排与亲密关系的期待匹配度 |
| E11 | 未婚污名化标签 | 中性表述「未婚」 |
| E12 | 外貌贬损词 | 镜像/镜头可能低估，建议自然光正脸照 |

**为何不写原文**：这是一份会被反复阅读的**工作文档**，不是取证现场。逐字取证在 `evidence.quote`（豁免扫描、一字不改）；本文档只需要传达「哪类表述要改成什么」。

## 五、验收标准（自检后回报）

```bash
node tools/check_rules.mjs knowledge/rules.part.0X.json
```

必须通过，且**零告警**（告警也视为未完成）。校验器会查：

- 规则有 `machine` 或标了 `advisory`
- `machine.when` 的 op 与 field 合法（field 必须在 `facts.json` 里）
- `machine.then[].kind` 合法
- 每条 evidence 的 aweme_id 真实存在、账号归属正确、**引文能在转写里溯源**
- 面向用户的文本过伦理门禁（P0 命中即报错）
- band 有结构化 `targetProfile`
- composites 有 anchors

另跑一次案例回归，报告你自己的部分带来的变化：

```bash
node tools/case_regression.mjs
```
